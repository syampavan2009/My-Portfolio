## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Project rules

- All portfolio copy and links live in `src/content/portfolio.ts`; section components only render it — keeps personal details editable in one place.
- The portfolio is one scrolling page (`/`) with in-page anchors, because the brief explicitly asked for smooth scrolling to sections and active-section highlighting.
- Electric visual motifs (glass, electric-card, electric-arc, grid-lines) are `@utility` classes in `src/styles.css`; reuse them instead of one-off glow styles.
- Theme: light tokens on `:root`, dark tokens on `.dark` (toggled on `<html>`, saved in localStorage, applied by an inline head script to avoid flashes); themed images render both variants with `dark:hidden` / `hidden dark:block`.
